# Phase 5 — Operator HMI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline, one session). Skills: `isa101-hmi`, `codesys-st-conventions`, `impeccable` (one critique pass, Task 8). Steps use checkbox syntax.

**Goal:** An ISA-101 high-performance operator HMI in the CODESYS application as a native Visualization (TargetVisu + WebVisu): 8 screens, role-gated commands, alarm list with acknowledge and history, recipes and production KPIs. A demonstrable subset (Overview + Alarms + Robot/Manual) runs live after Milestone A (Task 4); every later screen is additive.

**Architecture:** Three layers.

1. **Machine interface (unchanged):** `GVL_Hmi` / `GVL_Bridge` stay as they are, so the existing PLC specs and the Python bridge keep working.
2. **HMI layer in ST (folder `Hmi`):** screen buttons write only to `GVL_HmiPanel`. `FB_HmiPanel` gates each command by role and PackML state, then forwards to `GVL_Hmi` / `PRG_Recipe_Cell`. `FB_HmiView` derives display data into `GVL_HmiView`. `PRG_Hmi` (thin) runs both in `MainTask`.
3. **Screens:** described with the MCP tool (`hmi_template` → `hmi_save_screen` → `hmi_screenshot`) and built natively with `hmi_export_codesys` (`Visu_<Screen>`, alarm group `AG_HMI`, alarm history, `VISU_TASK`). They bind to `GVL_HmiView`, `GVL_HmiPanel`, `GVL_Bridge`, `GVL_Params` and FB instance paths.

**Tech Stack:** CODESYS 3.5.22.40, CODESYS MCP toolkit (`hmi_*`, `alarm_*`, `codesys_sim_test`, `export_sources`), Control Win V3 soft-PLC for the live check.

**Spec:** `docs/specs/2026-11-23-system-design.md` §5.3–5.5, §9, §15; ADR 0007.

*Plan drafted by an architecture advisor (Fable 5.2) on 2026-11-25 at the owner's request; the owner's priority: the PLC and its HMI are the core of the course, the AI is an addition.*

## Global Constraints

- `docs/conventions.md` §1: prefixes, `qualified_only`, thin `PRG_*`, FB header comments, no magic numbers. English. Conventional Commits, no AI attribution. Branch `phase/5-hmi`, one PR.
- **Tests first:** every PLC task writes `tests/plc/hmi_*.json` before the code (RED) → compile (check_all, deep) 0/0 → `codesys_sim_test` green → `export_sources`.
- **No logic in the visualization:** no ST in element properties, no enum-to-text on screen; texts, permissives and scaled values come from `FB_HmiView`.
- **`FB_AlarmHandler` is the single alarm truth:** native CODESYS alarms mirror its bits and never drive PackML.
- **Generated objects are not hand-edited** (`Visu_*`, `PRG_HMI_*`, `PRG_Recipe_Cell`, `AG_HMI`): change the screen description and re-export.
- **FB-internal `VAR`s are not read from ST:** add outputs or methods to `FB_SortingCell` instead (the visualization and tests may bind to instance paths).
- **Known tool limits, accepted:**
  - The native export shows trends as values; charts live in the browser HMI (`open_hmi`).
  - There is no animated motion on screen; the twin viewer shows motion.
- **Cut order if time runs out:** Task 7, then the Vision half of Task 6, then the OEE breakdown of Task 5. Never cut the PLC tests or Tasks 1–4.

## Review Focus

1. **Command without role or in the wrong state:** `GVL_Hmi` stays untouched and `GVL_HmiView.sDenied` says why. Tests: `start_denied_when_logged_out`, `recipe_apply_denied_in_execute`.
2. **Jog stuck** (browser closed, logout, mode change mid-press): jog bits drop when mode ≠ Manual, state ≠ Execute, role < Maintenance, or the press exceeds `JOG_MAX_HOLD`. Test: `jog_released_on_logout`.
3. **Acknowledge never hides a live condition and never restarts the cell.** Tests: `ack_one_keeps_others_pending`, `ack_keeps_active_alarm_listed`.
4. **The mode selector shows the actual mode, not the request.** Test: `mode_request_in_execute_not_applied`.
5. **Colour discipline and regression:** Execute and Idle are neutral grey on every screenshot; red and amber only for alarms and abnormal states; all earlier PLC specs still pass.

## Fixed Values

| Item | Value |
|---|---|
| Canvas | 1920×1080, 12×8 tile grid, 8 px spacing, also WebVisu |
| Theme | `light` on all pages; accent `#2F5D8A` (operable elements and set-points only) |
| Grey palette | background `#D9D9D9`, card `#E8E8E8`, line/symbol `#595959`, text `#1F1F1F`, secondary `#5F5F5F`, inactive `#A6A6A6` |
| Alarm colours (ISA-18.2, nothing else) | P1 Critical `#D32F2F`, P2 Error `#E8710A`, P3 Warning `#F2C200`, P4 Info `#7A5EA8`; tool tones: Critical/Error → `alarm` (prefix P1/P2), Warning → `warning` (P3) |
| State tones | Execute, Idle, Stopped, Complete: `neutral`. Held, Suspended and acting states: `warn`. Aborting, Aborted: `alarm`. Manual mode: `accent` hand sign. Never `ok` green |
| Symbols | custom SVG, outline only: `robot6`, `bin`, `camera`, `gripper`; standard `conveyor`, `sensor` |
| Navigation | left rail: Overview (home), Robot, Vision, Alarms, Trends, Recipes, Production, System; Overview is the start page |
| Frame (every page) | `machine` block (PackML state + `GVL_HmiView.sStateDetail`; Start/Stop/Reset; mode Production/Maintenance/Manual); top bar: User, Recipe, Parts/min, Active alarms |
| Roles | `E_UserRole`: None 0, Operator 1, Maintenance 2, Engineer 3; PLC-side PIN login, auto-logout after `T#10M` without a command |
| Permissions | Operator: Start, Stop, Hold, Unhold, Reset, Ack. Maintenance adds Clear, Abort, mode change, jog, override, shift reset, recipe apply. Engineer adds parameter edit and recipe save |

Deviation from spec §9.2: the login is implemented in ST, not VisuUserMgmt. The course grades PLC code, it can be tested in simulation, and it avoids a second login. Recorded in ADR 0010.

### Task 2: PLC — roles, login, command gating

**Objects (folder `Hmi`):** `E_UserRole`, `GVL_HmiPanel`, `GVL_HmiView`, `FB_HmiAccess`, `FB_HmiPanel`, `PRG_Hmi` (in `MainTask`), `Tests/PRG_TestHmi`. PINs and `tAutoLogout` go in `GVL_Config` (demo credentials, not OPC UA published). Add `JOG_MAX_HOLD : TIME := T#10S`.

- **`GVL_HmiPanel` (written by the visu):** `xStart, xStop, xReset, xHold, xUnhold, xClear, xAbort, xAckAll, eAckId, iModeSelect, axJogPlus/axJogMinus[1..6], rOverride, eLoginRole, diPin, xLogin, xLogout, iRecipeSelect, xRecipeApply, xRecipeSave, xShiftReset`.
- **`FB_HmiPanel`:**
  - Rising edge + permission + state → `GVL_Hmi.eCommand` / `eModeRequest` / `xAlarmAck`.
  - Jog and override pass through only while permitted.
  - Buttons are cleared after one cycle.
  - Outputs `xMay*` and `sDenied` (cleared after 5 s).
- **`FB_HmiView` basics:** state-group BOOLs, `sState`, `sMode`, `sStateDetail`, `sPickStep`, `sUser`, `eRole`.

**Tests first:**
- `tests/plc/hmi_access.json`: `login_with_wrong_pin_rejected`, `login_operator_sets_role`, `logout_clears_role`, `auto_logout_after_idle`.
- `tests/plc/hmi_commands.json`: `start_denied_when_logged_out`, `operator_reset_and_start_reach_execute`, `operator_cannot_change_mode`, `maintenance_selects_manual_in_idle`, `mode_request_in_execute_not_applied`, `jog_only_maintenance_manual_execute`, `jog_released_on_logout`, `jog_released_after_max_hold`, `override_clamped`.

### Task 4: Screens v1 — Overview, Alarms, Robot; first native export (MILESTONE A)

**Overview:**
- Process mimic: conveyor with PE1/PE2 and the camera, robot with gripper, six bins with counts and full signs.
- Key values with scale and set-point: belt speed, parts on belt, override.
- Pick step text.
- Status lamps: E-stop, door, bridge, vacuum.
- Top-3 alarms; Hold/Unhold.

**Alarms:**
- 16 rows bound to `axAlarmPending[n]`, text from `GVL_AlarmDefs` with the P-prefix.
- Acknowledge all, Clear, Reset.
- Column "condition present" from `axAlarmActive`.

**Robot:**
- J1–J6 bars against the software limits.
- Following error with bands (warn 2°, alarm 5°) and worst joint.
- TCP X/Y/Z.
- Override set-point.
- 12 momentary jog buttons with a "Jog permitted" lamp; vacuum state.
- Login tile (until System exists).

**Steps:**
- `hmi_save_screen` ×3; screenshots with normal values and with an E-stop.
- `hmi_export_codesys`; compile 0/0; `alarm_list`.
- In simulation: log in, Reset, Start; screenshot Overview in Execute; force the E-stop, screenshot Alarms, `alarm_status`; ack, release, Clear, `alarm_history`.
- Live on the soft-PLC with WebVisu: Login → Reset → Start → Stop by hand; jog J1 in Manual and confirm it stops on release.
- `export_sources`; commit.

### Task 5: PLC — production statistics; Production screen

**`Framework/FB_ProductionStats`:**
- Outputs: `udiTotal, udiGood, udiRework, udiScrap, udiQuarantine, rDefectRatePct, rThroughputPpm` (rolling 60 s), `tLastCycle, rAvailability, rPerformance, rQuality, rOee, tSinceShiftReset`. Every ratio is 0 when its denominator is 0.

**Tests:**

## Risks

- **Native alarms may need their own acknowledge.** If so, bind rows to `axAlarmPending` only; the PLC acknowledge stays authoritative.
- **Enum writes from widgets.** The mode switch writes an INT (`iModeSelect`) that the PLC range-checks.
- **Demo licence.** Restart the runtime (about every 2 h) before live checks.
- **`FB_SortingCell` interface growth.** Re-run `cell.json` in Tasks 3 and 5.
